# DLUT 校园网一键修复

大连理工大学校园网**认证故障的一键诊断 / 修复**脚本（Windows）。

![platform](https://img.shields.io/badge/platform-Windows%2010%20%7C%2011-0078D6)

![license](https://img.shields.io/badge/license-MIT-green)
![campus](https://img.shields.io/badge/campus-LingShui%20%7C%20Panjin-orange)

连不上校园网、认证页显示「网络中断」时，**先跑一次诊断**（10 秒，不改任何配置）；如果确实是下面那两个已知根因，**再跑一次修复**。

> 本脚本只修「本机配置」故障。账号欠费、整栋楼都连不上这类问题它修不了——会明确告诉你该找谁。

## 快速开始

### 方式一：双击（推荐）

双击 `DLUT校园网一键修复_先阅读使用说明.bat`，会弹出菜单：

```
  [1] 只诊断    不改任何配置，不需要管理员，约 10 秒出结果
  [2] 一键修复  重建无线配置 + 清理 hosts，需要管理员权限

  按 1 只诊断 / 按 2 一键修复（15 秒不选则按只诊断处理）:
```

| 操作 | 结果 |
|---|---|
| 按 `2` | 弹出 UAC 提权窗口，点「是」后执行修复 |
| 按 `1` | 不弹 UAC，10 秒左右出结果，**不改动任何东西** |
| 15 秒不操作 | 自动按「只诊断」走，安全兜底 |

建议顺序：**先按 1 看诊断结果，再按 2 修复。**

### 方式二：命令行

```bat
DLUT校园网一键修复_先阅读使用说明.bat -diag      :: 只诊断，免管理员
DLUT校园网一键修复_先阅读使用说明.bat -fix       :: 直接修复，自动提权
DLUT校园网一键修复_先阅读使用说明.bat -fix -y    :: 修复且不再问「是否切回原网络」
```

| 参数 | 作用 |
|---|---|
| `-diag` | 只诊断，不修改任何配置，不需要管理员 |
| `-fix` | 直接进入修复，不弹菜单 |
| `-y` | 跳过交互确认（包含结束时「是否切回原网络」） |
| `-panjin` / `-lingshui` | 手动指定校区常量（默认会扫描无线范围自动判断） |
| `-nopause` | 结束后不停留，直接退出 |

## 能修什么 / 不能修什么

| 现象 | 能否修复 |
|---|---|
| 认证页提示「网络中断」「不在 IP 地址」 | ✅ 这正是目标场景 |
| IP 变成 `169.254.x.x`（APIPA） | ✅ |
| 昨天还能用，今天突然连不上，同一台电脑 | ✅ 值得一试 |
| 提示账号欠费 / 流量用尽 / 账号被锁 | ❌ 去 [tulip.dlut.edu.cn](http://tulip.dlut.edu.cn) 自查缴费 |
| 室友也连不上、整栋楼都连不上 | ❌ 楼宇交换机或校园网故障，直接报修 |
| 需要密码 / 802.1X（WPA2-企业）的网络 | ❌ 脚本生成的是**开放式**配置，802.1X 的 profile 字段完全不同 |
| 无线网卡在设备管理器里是黄叹号 | ❌ 驱动问题，需重装驱动 |
| 学生机没有管理员权限 | ⚠️ 只能跑 `-diag` 诊断，修复会被安全跳过 |

**支持校区**：凌水校区 `DLUT-LingShui`（已实测）、盘锦校区 `DLUT-panjin`（常量未实测，会打印提示）。

## 它到底改了什么

修复模式共 8 步，**所有改动都会先备份**：

| 步骤 | 做什么 | 是否修改系统 |
|---|---|---|
| 1 | 体检网卡、当前所连 SSID、IP | 只读 |
| 2 | 备份 hosts 和当前无线配置 | 只新增备份文件 |
| 3 | 检查 WLAN 服务、读取配置状态 | 只读 |
| 4 | 检查 hosts 里有没有被写死的认证域名 IP | **会**：把失效记录注释掉（不删除） |
| 5 | 重建 `DLUT-LingShui` 的无线配置 | **会**：删除后重建这一个配置 |
| 6 | 连接校园网，检查是否拿到 IP | **会**：可能断开你当前连的 Wi-Fi |
| 7 | 检查网关、认证服务器、域名解析、认证页 | 只读 |
| 8 | 打开认证页，打印备份与回滚命令 | 只打开浏览器 |

几个关键设计：

- **备份位置**：脚本同目录的 `backup\`（`hosts.bak`、`WLAN-<SSID>.xml`）；该目录不可写时退到 `%TEMP%\dlut-net-backup`。
- **hosts 只注释不删除**，被处理的行变成 `# disabled 2026-09-15 stale hardcoded portal IP: ...`，随时可还原。
- **只动认证域名**：正则要求行首是 IP 且 `auth.` 前有空白，所以 `oauth.xxx` 这类无关记录不会被误伤；其它 `*.dlut.edu.cn` 记录只报告不修改。
- **只影响无线网卡**：第 6 步的释放/续租带接口名（`ipconfig /release "WLAN"`），不会碰有线、VPN、热点这些网卡的租约。
- **提权后重新校验**：每个写操作前都会复核管理员身份，不是管理员就整段跳过，**不会**在缺权限时先把配置删掉。

**安全声明**：脚本是纯文本 bat（内联 PowerShell），**不联网下载任何东西、没有混淆或加密**，可逐行审阅后再运行。

## 输出怎么读

| 标记 | 含义 |
|---|---|
| `[OK]` | 这一项正常 |
| `[INFO]` | 说明性信息 |
| `[WARN]` | 有异常但不致命，脚本可能已跳过某项 |
| `[FAIL]` | 这一项失败，需按提示处理 |

关键判读：

- `WLAN IPv4` 是 `10.x` / `172.x` → 拿到校园网地址，正常
- `WLAN IPv4` 是 `169.254.x.x` → **没拿到 IP**，这就是「网络中断」的直接原因
- `认证页 HTTP 302` → Portal 劫持生效，链路已通，去浏览器登录即可
- `认证页无响应` → 已登录认证时不响应属正常，不是故障

## 回滚

```bat
:: 还原 hosts（需管理员）
copy /y "backup\hosts.bak" "C:\Windows\System32\drivers\etc\hosts"

:: 还原原来的无线配置
netsh wlan add profile filename="backup\WLAN-DLUT-LingShui.xml" user=all
```

修复后无线配置是**手动连接**模式（避免校园网异常时把电脑从热点上拽走）。想改回自动连接：
设置 → 网络和 Internet → WLAN → 管理已知网络 → `DLUT-LingShui` → 勾选「自动连接」。

## 还是不通

1. **账号侧清绑定**：登录 [tulip.dlut.edu.cn](http://tulip.dlut.edu.cn) → 自助服务 → 认证上网服务 → 在线信息 → **把全部设备强制下线**，再重新认证。
2. 确认套餐流量是否用完、账号是否欠费。
3. 关掉下载器 / BT / 多开浏览器（短端口耗尽会拖慢认证页）。
4. 报修：网信中心 **84707007**（盘锦 0427-2631978），或 i大工 App → 网络自助。

### 不想跑脚本？手动版

```bat
:: 1) 忘记并重连校园网
::    设置 → 网络和 Internet → WLAN → 管理已知网络 → DLUT-LingShui → 忘记，然后重连

:: 2) 清掉 hosts 里写死的认证域名
::    记事本以管理员打开 C:\Windows\System32\drivers\etc\hosts
::    把形如  202.118.66.117 auth.dlut.edu.cn  的行前面加 # 注释掉
::    真正的认证地址是 202.118.66.137，不是 .117

:: 3) 刷新租约
ipconfig /release "WLAN"
ipconfig /renew "WLAN"
ipconfig /flushdns
```

## 常见问题

**会丢我的 Wi-Fi 密码吗？**
不会。`DLUT-LingShui` 是开放式网络，本来就没有密码；其它 Wi-Fi 的配置完全不受影响。

**会影响我家的 Wi-Fi / 手机热点吗？**
不会。只删并重建 `DLUT-LingShui` 这一个配置，也不动其它网卡的 IP。唯一影响是修复过程中会连到校园网，可能把你从当前 Wi-Fi 切走（会先问你，结束时还会问要不要切回去）。

**每次上网都要跑一遍吗？**
不用。这是修一次就好的工具，只在出问题时跑。

**它会不会误改 hosts 里别的东西？**
不会。只匹配「行首是 IP、后面跟着 `auth.` 域名」的有效行，且是注释而非删除，原文件已备份。

**为什么不做成 .exe？**
bat 可读、可审阅、无需签名，对这类需要改系统配置的工具更透明。

## 故障原理（两个根因）

本脚本由 2026-09-14 一次实际故障排查复现而来。那次的现象是认证页显示「网络中断」，最终定位到**本机两处配置残留**（不是账号问题，也不是学校服务器故障）：

| # | 根因 | 证据 |
|---|---|---|
| 1 | **无线配置文件损坏** | 一次网络重置后接口 GUID 变化；`netsh wlan connect` 报「配置文件指定的网络无法用于连接」。此时 Windows 会退化成「不使用配置文件连接」，MAC 与 IP 绑定关系异常，**DHCP 被持续 NACK** |
| 2 | **hosts 硬编码了失效的认证 IP** | `202.118.66.117 auth.dlut.edu.cn` 是手工写入的旧地址；实测校内 DNS 给出的真实地址是 **`202.118.66.137`**，认证页因此永远打不开 |

排查用到的四个取证点（脚本已内置前三个的判据）：

| 数据源 | 看什么 |
|---|---|
| `Microsoft-Windows-Dhcp-Client/Admin` 事件日志 | 事件 **1002**（错误）= IP 租约被 DHCPNACK 拒绝，铁证 |
| `Microsoft-Windows-WLAN-AutoConfig/Operational` | 事件 4000/4001 成对出现 = 做过「网络重置」；接口 GUID 变化 = 配置大概率损坏 |
| `netsh wlan connect` | 报「网络无法用于连接」= 配置损坏，必须重建 |
| `C:\Windows\System32\drivers\etc\hosts` | 认证域名被钉到失效 IP（高校认证域名通常是校内专有域名，公网 DNS 无解析，最容易被手工写 hosts） |

修复动作三件：**重建无线配置**（开放 / 手动连接 / **关闭 MAC 随机化**）→ **注释 hosts 里的失效硬编码** → **强制刷新租约**。

> 校园网普遍按 MAC 做 IP / 账号绑定，**不要开 MAC 随机化**，否则 DHCP 与认证会双重失败。

## 常量表 / 换校区适配

| 项 | 值 |
|---|---|
| 校园网 SSID | `DLUT-LingShui`（凌水）／`DLUT-panjin`（盘锦） |
| `DLUT-LingShui` 的 SSID 十六进制 | `444C55542D4C696E6753687569` |
| 认证页 | `auth.dlut.edu.cn` |
| 认证服务器 | `202.118.66.137` ← **不是 `.117`** |
| 校内 IPv4 网段 / 网关 | `10.5.0.0/16`，网关 `10.5.0.1` |
| 校内 DHCP 服务器 | `202.118.66.172` |

（`SSIDHEX` 会被 PowerShell 动态重算，重算失败才用硬编码值）。其他学校通常也能用，只要认证方式是**开放网络 + 网页 Portal 认证**。
